## Terminal Quality Assessment

A rigorous inspection of `TerminalScreen.kt`, `NativeSpawnProcess.kt`, and `cpp/pocket_spawn.c` was performed to determine the exact capabilities and limitations of Mobile Harness's terminal subsystem:

### 1. Architectural Reality: Not a Real Terminal Emulator
* **What is present:**
  - `cpp/pocket_spawn.c` correctly invokes POSIX PTY APIs: `posix_openpt()`, `grantpt()`, `unlockpt()`, `ptsname()`, `ioctl(slave_fd, TIOCSCTTY, 0)`, and `ioctl(slave_fd, TIOCSWINSZ, &size)`.
  - A background Java thread (`NativeSpawnProcess.outputPump`) reads bytes from the PTY master file descriptor and writes them to an output capture file.
* **What is missing on the UI side:**
  - **No Terminal Matrix / Character Grid:** Unlike real terminal emulators (Termux, Alacritty, GNOME Terminal) which maintain an `N x M` character cell matrix with cursor tracking, `TerminalScreen.kt` simply uses a Jetpack Compose `Column` wrapped in `verticalScroll(terminalScrollState)` and renders lines as static `Text()` composables!
  - **No Alternate Screen Buffer (`\e[?1049h`):** When full-screen terminal programs open, they signal the terminal to switch to the alternate buffer. Mobile Harness ignores this completely, meaning full-screen apps overwrite the scrollback history.
  - **No In-Place Cursor Addressing:** Escape sequences that move the cursor (e.g. `\e[H`, `\e[2J`, `\e[10;20H`) are not parsed into screen coordinates. `MainViewModel.kt` line 227 defines `sanitizeTerminalOutput(text: String): String = text`, which passes raw text without even stripping or translating ANSI cursor codes.
  - **No Interactive Raw Character-by-Character Input:** Users interact with the terminal by typing in a standard Android `BasicTextField` and pressing "Send" (Enter). Single-character key events are not streamed immediately to the PTY.

### 2. Can Interactive Tools Run?

| Tool | Status | Observed Behavior & Code Evidence |
| :--- | :--- | :--- |
| **Sequential Commands (`ls`, `git`, `python`, `npm`)** | **WORKS** | Batch output streams sequentially down the Compose column. Exit codes and text display correctly. |
| **`vim` / `nano`** | **BROKEN** | Pressing keys requires typing in the input box and pressing Enter. Cursor positioning fails; screen redraws produce duplicated garbled lines. |
| **`htop` / `top`** | **BROKEN** | Periodic screen refreshes create an infinite scrolling list of ANSI escape codes rather than an in-place updating dashboard. |
| **`tmux` / `screen`** | **BROKEN** | Fails to initialize alternate screen and split panes properly; terminal window resize events (`SIGWINCH`) are not dynamically bound to Compose layout changes. |
| **Claude Code Interactive TUI** | **BYPASSED** | Mobile Harness **never runs Claude Code's interactive TUI** in the terminal. Instead, `ClaudeRuntimeBridge.kt` explicitly launches Claude with `--input-format stream-json --output-format stream-json`, completely avoiding the broken terminal renderer! |

### 3. Recommendation for the New Project
> [!IMPORTANT]
> To support real interactive tools (`vim`, `htop`, `tmux`, and interactive agent TUIs) and provide a professional developer experience, our version must replace this simple Compose Text scrollback with a **true terminal emulation engine**:
> - Either integrate the proven **Termux Terminal View (`com.termux.terminal`)** component, or
> - Embed a high-performance **Xterm.js** instance inside an optimized hardware-accelerated `WebView`.
